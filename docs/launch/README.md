# Rulefall Launch Kit

This kit contains platform-specific drafts for the v0.1 launch. Edit them to reflect the final deployment, attach only real product media, and participate in each community's discussion.

## Launch Principles

- Post once per relevant community from a real maintainer account.
- Disclose that you built the project.
- Lead with the problem and working demo, not a request for stars.
- Adapt the post to the community; do not cross-post identical copy in bulk.
- Answer questions, accept criticism, and update semantic mistakes quickly.
- Do not buy votes, trade stars, mass-DM users, or coordinate artificial engagement.
- If a community disallows self-promotion, do not post there.

## Asset Checklist

- Online GitHub Pages URL tested in a signed-out browser before describing it as available.
- Repository description and topics set from [repository-metadata.md](repository-metadata.md).
- One accurate screenshot or a 15–25 second recording showing the lifecycle scrubber. Do not use a mockup as if it were the product.
- v0.1.0 release published from [release notes](../releases/v0.1.0.md).
- CI green and issue templates enabled.
- README links checked after the repository becomes public.

## Suggested Sequence

1. Publish the repository, Pages deployment, and v0.1.0 release.
2. Share one concise post on the maintainer's existing network.
3. Submit Show HN only when the maintainer can stay available for discussion.
4. Post to one or two genuinely relevant communities after checking their current rules.
5. Collect questions and turn repeated confusion into docs or fixtures.
6. Share substantive follow-ups only when there is a meaningful release, investigation, or benchmark.
