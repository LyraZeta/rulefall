# Rulefall v0.1.0: The Waterfall Release

Released: August 14, 2026

Your coding agents do not read the same repo. Rulefall v0.1.0 makes that mismatch visible as a lifecycle waterfall.

Choose a working directory and target file, then move from startup to discovery to edit. Rulefall compares Codex, Claude Code, Cursor, and GitHub Copilot and explains which repository instruction files are loaded, deferred, ignored, shadowed, or truncated.

## Highlights

- Four agents, one comparable event vocabulary.
- Built-in `orbit-payments` scenario for a zero-setup tour.
- Local folder access with ZIP import fallback, partial-import warnings, and documented limits for file size, total text, entry count, archive size, and suspicious compression ratios.
- Working-directory and target-path controls.
- Per-event source, reason, timing, confidence, bytes, and token estimate.
- Portability and context summaries.
- Browser-generated PNG export; exported reports can contain workspace names, repository paths, selected context, and visible instruction excerpts.
- Static, local-only analysis: no backend, telemetry, account, upload, or model call.
- English and Simplified Chinese documentation.

## What v0.1 Is Not

Rulefall is a lifecycle conformance simulator, not a full configuration inventory, linter, LSP, live-agent inspector, or proof of model compliance. It models a deliberately narrow set of documented repository instructions and labels conditional or incomplete semantics.

Read [Semantics and Confidence](../SEMANTICS.md) before using a trace as evidence, and file a [semantic gap](https://github.com/LyraZeta/rulefall/issues/new?template=semantic-gap.yml) when current provider behavior differs.

## Try It

Try the [online simulator](https://lyrazeta.github.io/rulefall/), or run it locally:

```bash
git clone https://github.com/LyraZeta/rulefall.git
cd rulefall
corepack enable
pnpm install
pnpm dev
```
